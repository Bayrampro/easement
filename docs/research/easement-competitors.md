# Emerging architecture enforcement competitors

Checked on 2026-11-04 against public first-party documentation. This is a capability comparison, not a benchmark: the tools were not installed or exercised. “Not verified” means the cited material does not establish the feature, not that the feature cannot exist.

The strongest counterexamples to broad uniqueness claims are Architect Genesis for a polyglot rules CLI with an agent interface, and MKanhan's archlint for an explicitly agent-oriented polyglot boundary guardrail. Baselines, JSON, MCP, and compiler-backed polyglot graphs also exist elsewhere; each needs a narrower comparison than a unique-feature claim.

| Tool | Verified overlap | Material limit or distinction |
| --- | --- | --- |
| [Architect Genesis](https://github.com/camilooscargbaptista/architect#architecture-rules-architectrulesyml) | Documents Tree-sitter analysis for TypeScript, Python, Go, Java, Rust, Ruby and PHP. YAML rules include forbidden imports between path groups, cycle prohibition and quality gates; `architect check` supplies a CI exit status. Its MCP server exposes `check_rules` alongside analysis and suggestions. | Direct overlap with “polyglot architecture rules for coding agents.” The README establishes AST parsing, not compiler-resolved references. It documents score history/regressions; an easement-style violation baseline/diff was not verified. |
| [MKanhan/archlint](https://github.com/MKanhan/archlint/blob/master/README.md) | MIT Python script, explicitly built as a Claude Code edit/stop hook. Reads layers, allowed edges and `forbid` rules from a blueprint in `CLAUDE.md`, `AGENTS.md` or `ARCHITECTURE.md`. Covers Python, TS/JS, Go and Rust, with path alias/module resolution. CLI `check` exits 1 on drift; strict hook mode blocks completion. | Explicitly import/glob analysis, not semantic analysis. External imports are ignored. Baselines, cycle detection, SARIF, Java and C# are listed as separately licensed Pro features rather than capabilities of the public lite implementation. |
| [mshogin/archlint](https://github.com/mshogin/archlint#readme) | Go-primary CLI with external Rust/TS structural scanners. YAML includes layers and allowed dependencies. Documents a baseline gate blocking new error violations, `diff main..feature --format json`, and MCP tools including `analyze_change`, `get_dependencies` and `check_violations`. | The README calls Go the primary target and describes Rust/TS as structural graph scanners; it does not establish equivalent semantic accuracy or rule coverage across all three. It is a different project from the two other tools named archlint in this table. |
| [archlinter/archlint](https://github.com/archlinter/archlint#readme) | AST architecture-smell and layer-rule CLI with snapshot/baseline comparison and MCP integration. Its [CLI reference](https://archlinter.github.io/archlint/cli/) explicitly lists JSON snapshots and comparison against a baseline. | TS/JS only. Good counterexample to baseline/diff/MCP uniqueness, not to broad language coverage. |
| [ArchGuard](https://github.com/archguard/archguard#readme) | Architecture governance platform with scanner CLI, CI plugin, custom rule governance, architecture DSL and cycle/coupling analysis. Chapi support matrix spans several languages. | Capability matrix is uneven: syntax parsing is broader than function-call/package analysis or real-world validation. Its README labels MCP as a proposal, so it should not be counted as a shipped agent interface. Baseline gating was not verified. |
| [ArchGraph](https://docs.archgraph.dev/supported-languages) | Sixteen-language graph with tree-sitter and SCIP-backed resolution where available, heuristic fallback, and a report of the resolution method actually used. [MCP tools](https://docs.archgraph.dev/mcp-tools) use JSON and include import-cycle detection, impact and dependency queries. | Adjacent code-intelligence service, not a verified native architecture-policy gate: the tool reference does not establish declarative allowed/forbidden boundaries with CI failure or debt baselines. Documentation explicitly warns that an indexer existing does not mean the published image can run it; C/C++ and default C# compiler resolution have deployment limits. |

[Arch-Go](https://github.com/arch-go/arch-go#supported-rules) is a narrower precedent: Go import allow/deny rules for internal, standard-library and third-party dependencies, plus package-content and function checks. It is not polyglot. [Archgate](https://github.com/archgate/cli#readme) is another adjacent agent-governance approach: ADRs have companion TypeScript checks, and `archgate check` reports file/line/ADR and fails CI. That establishes executable team decisions, not a built-in multi-language semantic dependency engine.

## Implication

Inference: easement's defensible comparison is the combination and quality of its particular workflow: a shared architecture model across its supported languages, compiler-derived dependencies where supported, agent-readable commands, and explicit trust/partial-analysis reporting. The existence of these competitors rules out claiming that multilingual architecture enforcement, agent integration, baselines, or compiler-backed graphs are individually unique. Establishing that the entire combination is unique would require implementation-level comparison and representative fixtures, beyond this documentation survey.
